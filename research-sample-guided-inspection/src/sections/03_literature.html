13.2 The methods you need to know, explained

The research brief lists 18 methods. They fall into six families. For each family: how it works in simple terms, the technical core, and the verdict for this project. Selection: CORE = part of the proposed system; BASELINE = compared against; OPTIONAL = extension; no tag = background only.

Family 1: Memory and nearest-neighbour anomaly detection

Feature-based nearest-neighbour matching CORE. Simply: describe every small region of the normal images with a vector of numbers; for a new image, ask whether each region has a close twin among the normal regions. Technically: anomaly score = distance to the k-th nearest neighbour in a bank of pretrained features. No training; robust to small data; cost grows with the bank, which is controlled by subsampling.

SPADE [[spade]] BASELINE. Retrieves the K most similar normal images using global features, then does pixel-wise nearest-neighbour matching in their multi-scale feature pyramids. It introduced the "correspondence with similar normal images" idea that this project uses for alignment-aware matching.

PatchCore [[patchcore]] CORE. Builds a memory bank of locally aggregated mid-level patch features (Wide-ResNet-50 layers 2 and 3), reduces it by greedy coreset subsampling (keeping a subset that covers the feature space), and scores each test patch by its nearest-neighbour distance; the image score is the highest patch score, re-weighted by local density. Reported up to 99.6% image AUROC on MVTec AD. It is the template for the proposed reference memory.

AnomalyDINO [[anomalydino]] BASELINE. The same patch-matching principle with DINOv2 ViT features [[dinov2]], designed for the few-shot case; 96.6% 1-shot image AUROC on MVTec AD. The strongest simple few-shot baseline.

Family 2: Distribution, flow and reconstruction models

PaDiM [[padim]] BASELINE (aligned data only). Fits a Gaussian per patch position and scores by Mahalanobis distance. It needs many normal images to estimate covariances and assumes alignment, so it serves as a "position-aware" comparison after registration, not as a few-shot method.

FastFlow [[fastflow]]. Learns a normalizing flow that maps normal features to a simple Gaussian, giving an exact likelihood per location. Needs many normal images; background only.

DRAEM [[draem]] OPTIONAL. Trains a reconstruction network and a segmentation network on normal images with pasted synthetic anomalies. Not few-shot, but its anomaly-synthesis recipe is reused for the defect-injection benchmark.

Family 3: Student–teacher methods

Reverse Distillation [[rd]] and EfficientAD [[efficientad]] BASELINE (full-data upper bound). A student network learns to reproduce a teacher's features on normal images; disagreement marks anomalies. Both need per-category training on many normals. They show what is achievable when plenty of normal data exist, and EfficientAD sets a latency reference.

Family 4: Metric-based few-shot learning

Siamese networks [[siamese]]: two weight-sharing encoders embed two images; a learned distance says whether they match. Matching networks [[matchnet]]: classify a query by attention-weighted similarity to a labelled support set. Prototypical networks [[protonet]] CORE (for known-defect classes): each class is represented by the mean embedding (prototype) of its few examples, and a query takes the class of the nearest prototype. These are classification methods: they need examples of every class and are closed-set by design. In this project prototypes are used only for the optional known-defect memory, and always after the normal-reference test (Section 18.8).

Family 5: Encoders: CNNs, Vision Transformers and foundation features

CNN feature extraction (ResNet, Wide-ResNet, EfficientNet, ConvNeXt [[resnet,wrn,efficientnet,convnext]]) CORE: convolution layers produce feature maps whose mid layers combine local detail with some context. Vision Transformers [[vit]] split images into patches (e.g. 14 × 14 px for DINOv2) and relate them with self-attention; self-supervised DINOv2 features transfer well without fine-tuning [[dinov2]] CORE. CLIP-based methods (WinCLIP [[winclip]], InCTRL [[inctrl]], SEM-CLIP [[semclip]]) add language priors BASELINE. The encoder choice is an experimental variable (Section 18.4).

Family 6: Geometry, adaptation, continual and open-set learning

Image registration methods [[zitova,ecc,fmt,guizar,sift,orb,ransac]] CORE: estimate the transform between two images from intensities (phase correlation, Fourier–Mellin, ECC) or from matched keypoints (SIFT/ORB + RANSAC). Spatial Transformer Networks [[stn]]: a differentiable module that predicts and applies a warp inside a network; used by RegAD [[regad]] for feature-level registration BASELINE. Rotation-invariant features (GraphCore [[graphcore]]) BASELINE.

Test-time adaptation (e.g. Tent [[tent]], which updates normalisation parameters on unlabelled test batches by entropy minimisation) OPTIONAL: attractive for cross-wafer drift, but it adapts to whatever the test batch contains, including defects, so for anomaly detection it needs care. Continual learning and memory replay (EWC [[ewc]], replay buffers [[zhao2024pirb]], prompt memories [[ucad]]) OPTIONAL for encoder fine-tuning; the core system uses memory edits instead. Open-set anomaly detection (open-set recognition [[scheirer,openmax]], open-set supervised AD [[dra]]) CORE idea for Stage 8.

Selection

Core pipeline: classical registration (coarse rotation search + Fourier–Mellin + ECC refinement) → frozen multi-scale encoder (WRN-50 and DINOv2 ViT-S/14 compared) → PatchCore-style memory with alignment-aware nearest-neighbour search → prototype-based known-defect memory with open-set rejection → gated memory updates. Not implemented: FastFlow, Matching and Siamese networks, Tent (unless time allows).

15.2 Gap statement

Defensible research gap

Few-shot, reference-based anomaly detection with frozen pretrained features is established on natural-object benchmarks [[patchcore,anomalydino,univad]]. Learned registration [[regad]] and rotation-invariant features [[graphcore]] have improved few-shot detection under pose variation. Open-set recognition is studied for wafer maps [[shin2025]]. Continual learning has been benchmarked on fab SEM data [[prasad2024]]. Training-free memory correction from simulated expert feedback has been demonstrated on MVTec AD [[abbas]]. Semiconductor-specific work uses private data [[semclip,zhao2025seg,zhao2025ncd,dey2024]] and, in one line of work, argues against external references for IC images [[zhao2025seg]].

Within the literature we reviewed, we found no study that, on semiconductor die imagery with public, reproducible splits:

  1. measures whether geometric alignment or rotation invariance preserves or weakens genuine defects (not only whether detection accuracy holds), including orientation-dependent defects;
  2. performs pixel-level three-way triage (normal / known class / unknown) driven by normal references plus a small known-defect memory, evaluated by leave-one-class-out on expert masks;
  3. evaluates memory updates from imperfect engineer feedback (wrong labels, wrong locations) with quarantine, gating and rollback, under a held-out protocol that rules out memorisation;
  4. separates same-wafer, cross-wafer and cross-type transfer as distinct, explicitly defined evaluation conditions.

This is a gap in evaluated combinations and evaluation protocols, not a claim that the individual components are new.

What would close the gap (and how the project would respond)

If a paper appears that already performs items 1–3 on semiconductor data, the project becomes a reproduction-and-extension study on public data, focusing on whichever item remains open. A monthly literature alert is part of the risk plan (Section 26).

16.3 Recommended contributions for a student project

Prioritise these
  1. C2 · Defect-preserving alignment (highest priority). Clear gap, cheap to test (rotations and injected defects are fully controlled), and it produces a new, reusable evaluation tool (DPR). Feasible on public and synthetic data.
  2. C3 · Reference-guided unknown-anomaly localisation. Testable on public data with real expert masks (Carinthia-S, leave-one-class-out). Results are meaningful even if the answer is negative.
  3. C5 · Verified feedback adaptation under noisy feedback (if time allows). Builds directly on a 2026 preprint [[abbas]], so its novelty is the noisy-feedback robustness and the semiconductor setting. Simulation is cheap; the main risk is evaluation leakage, which the protocol addresses.

C1 is not a separate contribution but the shared experimental backbone: every result is reported for K = 1–10 and for the transfer splits. C4 (wafer-level context) is an optional extension because no public dataset links die images to wafer coordinates.
