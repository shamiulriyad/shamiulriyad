18Proposed Technical Methodology

The methodology follows the ten stages of the research brief. For each stage: what it does, which options were compared, what is recommended for the first implementation, and what can go wrong.

Any operation that is applied to the target must also be applied, identically, to the references, and every preprocessing choice is checked with the defect preservation ratio (Section 19.6) on injected defects before it is adopted.

Practical baseline (recommended first implementation)
  1. Coarse orientation: evaluate the four 90° rotations of the reference template against the target with normalised cross-correlation on downsampled images; keep the best.
  2. Residual rotation and scale: Fourier–Mellin (log-polar FFT) on the coarse-aligned pair; or a fine angle search in ±15°.
  3. Refinement: ECC with a Euclidean (rotation + translation) or similarity model on a Gaussian pyramid, using die-edge and seal-ring regions to avoid pitch ambiguity.
  4. Apply to the references, not the target: warp each reference into the target frame (bilinear), compute a validity mask for regions the references do not cover, and exclude them from scoring.
  5. Quality check: if the post-alignment correlation is below a threshold, flag the die as "alignment uncertain" and fall back to a rotation-augmented memory.

Limitations: large non-rigid distortions (e.g. SEM charging drift) are not modelled; periodic structures can still cause pitch-sized errors; very small dies with little structure may not align. All are measured by target registration error on synthetic data.

18.4 Stage 4: Feature extraction

What a feature vector is. A list of numbers (for example 1,024 of them) that describes a region of an image. A good encoder places similar-looking regions close together in this space, so "how different is this region?" becomes "how far apart are these vectors?".

What a feature map is. Encoders keep the spatial layout: a 256 × 256 image becomes, say, a 32 × 32 grid of feature vectors. Each grid cell describes a small patch of the image, its receptive field. Comparing feature maps cell by cell gives a spatial anomaly map.

Why multiple scales matter. Early layers describe fine detail (edges, small dots) at high resolution; deeper layers describe larger context (a via in an array, the end of a line) at low resolution. A 2-pixel missing via is visible in early layers; a large stain is better captured in deep layers. PatchCore uses mid layers 2 and 3 and averages each feature with its neighbours, a compromise between detail and context [[patchcore]].

Why tiny defects need spatially informative features. If one feature cell covers 16 × 16 pixels and a defect occupies 2 × 2 of them, the defect changes only a small part of that cell's description and can be lost in natural variation. Remedies: features from earlier layers, smaller stride, larger input (tiling at native resolution), or upsampling the image so that the defect spans more of a patch. Experiment F reports results by defect size so this effect becomes visible.

18.5 Stage 5: Reference memory

How the model "remembers" without retraining. Enrolment passes each reference through the frozen encoder and appends its patch features to a list, the memory M. That is the whole learning step. Inspection asks nearest-neighbour questions of M. Adding, removing or relabelling items changes the system's behaviour immediately and reversibly; no gradient descent is involved.

  • Feature bank (normal memory MN). All patch features of the aligned references, with metadata (reference ID, position, scale, memory version).
  • Coreset subsampling. Greedy selection of a subset that covers the bank (e.g. 10–25%), keeping search fast [[patchcore]]. With K ≤ 10 dies the bank is small, so subsampling may be unnecessary.
  • Nearest-neighbour matching with an alignment-aware window. Because references are aligned, a target patch at position p is first compared with reference patches near p (window of ±w cells). This is faster and stricter: a via-array patch cannot be "explained" by a similar via array elsewhere on the die. A global search is kept as a second score; disagreement between the two flags misalignment.
  • Prototype representations. Mean features of groups (e.g. of each defect class) for compact storage and classification [[protonet]].
  • Known-defect memory MD. Region features of verified defects, grouped by class, kept separate from MN so that defects never contaminate the normal memory.
  • Memory quality control. Before admission: remove features from low-quality images; detect outlier references (a reference whose patches are far from the other references' patches may contain a defect: leave-one-out scoring); de-duplicate; record provenance and version.

18.6 Stage 6: Anomaly detection

Feature distance and similarity. For each target patch feature, compute its Euclidean distance to the nearest memory feature (or 1 − cosine similarity). Distance 0 means "an identical patch exists in the references".

Normality and anomaly score. The anomaly score of a patch is that nearest distance; a normality score is its negative or a monotone transform. The image score A(x) is the maximum patch score, or the mean of the top-q% of patch scores, which is more robust to single noisy pixels.

Score normalisation. Distances depend on the encoder and the die type. To compare across die types, standardise with statistics from leave-one-out scoring of the references (each reference scored against the others) and the calibration normals: z = (s − μref) / σref.

Threshold selection. Choose τ so that a target false-alarm rate α on normal dies is met: τ = the (1 − α) quantile of image scores of held-out normals (for image decisions) or of pixel scores (for maps). With K = 1 and no held-out normals, build pseudo-normals by small random shifts, rotations and noise of the reference and score them. This underestimates natural variation, so α is then reported as optimistic. Thresholds are always selected on validation data, never on test data.

Confidence and uncertainty. Report (i) the margin (A − τ)/σref; (ii) agreement between the windowed and global nearest-neighbour scores; (iii) optionally, variation of the decision across the K leave-one-out sub-memories (a cheap ensemble). Low margin or disagreement sends the die to review. Scores can be mapped to calibrated probabilities with a validation set (isotonic regression or temperature-style scaling [[guo]]) when enough labelled validation data exist.

18.7 Stage 7: Defect localisation

  • Pixel-level anomaly maps: the patch score grid is bilinearly upsampled to image size and lightly smoothed (Gaussian σ ≈ 2–4 px). This smoothing affects the map, not the image, and is applied identically to all methods.
  • Patch-level localisation: the raw grid itself; useful when masks are coarse.
  • Segmentation: threshold the map at τpix; remove regions below a minimum area; report each connected region with area, peak score and mean score.
  • Bounding boxes: the tight box of each region, for comparison with box annotations (Wafer Surface Defect).
  • Multi-scale localisation: compute maps from two feature levels and combine them (maximum or mean), so that small and large defects are both visible; ablated in Experiment H.

Annotation needed for each output is listed in Section 17.8. Localisation is reported in the target's own coordinates, which is guaranteed by the "warp the reference" design.

18.8 Stage 8: Unknown defect detection

Three-way triage. The normal-memory test always runs first. Only regions that are anomalous are compared with known-defect prototypes; a region far from all known classes is reported as an unknown anomaly, and a region close to two classes is sent to review as ambiguous.

The decision for each anomalous region r uses two distances: to the normal memory (is it abnormal?) and to known-defect prototypes (is it something we know?).

  1. Known normal patterns: A(r) ≤ τn → normal.
  2. Known defect types: A(r) > τn and the nearest prototype distance dc* < τk with a clear margin to the second-nearest class → known class c*.
  3. Unknown suspicious patterns: A(r) > τn and dc* ≥ τk → unknown anomaly; low margin → ambiguous (review with top-2 candidates).

τk is set per class from the spread of that class's own examples (e.g. the maximum leave-one-out distance times a safety factor), so classes with few, tight examples get tight boundaries, as in open-set recognition [[scheirer]]. Because step 1 depends only on normal references, an unknown defect is always flagged as anomalous even if triage is wrong, which follows the design rule of [[dra]]. Unknown regions can later be clustered for engineer review, similar to novel class discovery [[zhao2025ncd]], but that is an extension.

18.9 Stage 9: Wafer-level analysis

Image-level defects vs wafer-map failure patterns. An image-level defect is a localised abnormality inside one die (a particle at pixel 412, 87). A wafer-map failure pattern is a spatial arrangement of abnormal dies across the wafer (an edge ring). They are different findings, computed from different data, and reported separately.

  • Die indexing: (row, column) from die extraction or metadata; wafer coordinates in mm from the die pitch.
  • Wafer-map visualisation: per-die image score Aij, per-die status, and per-die defect count/area (Figure {{fig:wafermap}}).
  • Defect clustering: DBSCAN on coordinates of suspicious dies; spatial autocorrelation (e.g. join-count statistics) to test whether failures are clustered or random.
  • Repeated spatial patterns: compare the binary suspicious-die map with WM-811K-style pattern classes using a wafer-map classifier trained on WM-811K, as an optional context label.
  • Context score (RQ7, optional): A′ij = Aij + λ · mean(A of neighbouring dies), to test whether spatial context improves die ranking. Risk: context can raise false alarms for good dies inside a cluster, so it is evaluated, not assumed.
  • Repeater detection: an anomaly at the same within-die position on many dies suggests a systematic (reticle- or design-related) cause, and also warns that such a defect may have contaminated the references.

Safe feedback workflow (recommended first):

  1. Record: every engineer action (confirm, reject, correct location, assign label, mark unknown) is stored with reviewer ID, time, die ID and the memory version that produced the result.
  2. Route by action:
    • Reject (false alarm) → candidate normal patches from the flagged region enter a quarantine buffer.
    • Confirm + label → region features become candidate known-defect items for class c.
    • Correct location → corrected mask defines which patches are defect and which are normal.
    • Mark unknown → region stored in an investigation set; it never enters the normal memory.
  3. Gate: a candidate normal patch is admitted only if (a) it is novel (its distance to MN exceeds the median nearest-neighbour distance among existing normals, a self-calibrating gate following [[abbas]]), (b) it is not close to any known-defect prototype, and (c) a second reviewer confirmed it, or the same pattern was independently rejected as a false alarm on at least n different dies.
  4. Version and regression check: admitted items create a candidate memory Mt+1. It is evaluated on a fixed held-out validation set of normal and defective dies (never used for feedback). It is accepted only if recall at the operating threshold does not drop and AUROC does not decrease beyond a tolerance; otherwise it rolls back to Mt.
  5. Drift monitoring: track the memory size, the share of feedback-derived items, the false-alarm rate on a fixed set of golden normal dies, and the detection rate on a fixed set of known defects (a "canary" set). Alarm if either drifts.
Why memory updates first

They need no GPU training, act immediately, and are fully auditable and reversible. They also directly test the question of the research brief, "does feedback improve detection or merely memorise samples?", because a held-out protocol can measure improvement on dies that never generated feedback. Fine-tuning is only worth adding if memory updates plateau.

19Mathematical Formulation

This section uses only distances, minima and averages. Every symbol is explained in plain English right after it appears.

19.1 Symbols

Symbols used in the formulation.
SymbolMeaning in plain English
R = {r1, …, rK}The reference set: K images of normal dies that the engineer provides.
xThe target die image we want to inspect (height H, width W pixels).
T, T̂The true and the estimated geometric transform (rotation angle θ, shift t, scale s) between a reference and the target.
fThe frozen feature encoder. f(x) is a grid of h × w feature vectors, each with C numbers. fp(x) is the vector at grid position p.
M = MN ∪ MDThe reference memory: normal patch features MN, plus optional known-defect prototypes MD = {μc}.
d(a, b)Distance between two feature vectors, here Euclidean: d(a, b) = ‖a − b‖. Small = similar.
s(p)Anomaly score of the patch at position p.
SThe spatial anomaly map: s(p) for every position, upsampled to H × W pixels.
A(x)The image-level anomaly score of the whole die.
τ, τpix, τkThresholds: for image decisions, for pixels, and for accepting a known class.
UThe feedback update function, which turns the memory at time t into the memory at time t + 1.

19.2 Conceptual flow

Reference dies R → feature extraction f(rk) → reference memory M → target features f(x) → feature comparison d(·, M) → anomaly map S → defect decision (A(x) > τ ?)

19.3 Enrolment

MN = ⋃k=1..K { fp( T̂k(rk) ) : p valid } (1)

In words: align each reference, run it through the encoder, and put every valid patch feature into the memory. "Valid" excludes border regions with no image data after warping. If the memory is large, a coreset subset is kept.

19.4 Anomaly scoring

s(p) = minm ∈ MN(p) ‖ fp(x) − m ‖ (2)

In words: for the patch at position p of the target, find the most similar normal patch in the memory and take the distance. MN(p) is either the whole normal memory (global search) or only the reference patches within a window around p (aligned search). A large distance means "nothing like this exists in the references".

S = Gσ ∗ Upsample( [ s(p) ]p ),    A(x) = mean of the top-q% values of s (3)

In words: the anomaly map is the grid of patch scores, enlarged to the image size and lightly smoothed (Gσ is a Gaussian blur of width σ applied to the map, not to the image). The die's score summarises its worst patches; q = 1% is a typical choice, and q → 0 gives the maximum.

decision(x) = anomalous if A(x) > τ,    τ = Quantile1−α{ A(x′) : x′ normal, held-out } (4)

In words: the threshold is set so that only a fraction α (e.g. 1%) of normal validation dies would be flagged. Pixels whose map value exceeds τpix (chosen the same way on pixel scores) form the predicted defect mask.

19.5 Known / unknown triage

c* = argminc ‖ g(r) − μc ‖,    y(r) = known:c* if ‖g(r) − μc*‖ < τk,c*, otherwise unknown (5)

In words: g(r) is the average feature of an anomalous region r; μc is the prototype (average feature) of known class c. The region takes the nearest class only if it is close enough to it; otherwise it is "unknown".

19.6 Defect preservation ratio (proposed evaluation)

DPR(P) = sdefect( pipeline with step P ) / sdefect( reference pipeline without P, ideal alignment ) (6)

In words: inject a defect with a known mask, and measure its peak (or mean) anomaly score with and without a processing step P (an alignment variant, a denoising filter, a resize). DPR ≈ 1 means the step keeps the defect as visible as before; DPR < 1 means the step weakens it. Reported by defect size and type. Because the injected defect is known exactly, DPR isolates the effect of P from the rest of the pipeline.

19.7 Feedback update

Mt+1 = U(Mt, Ft) = ( MN,t ∪ { z ∈ Ztnormal : gate(z) } ) ∪ ( MD,t ⊕ Ztdefect ) (7) gate(z) = [ minm∈MN,t ‖z − m‖ > δt ] ∧ [ minc ‖z − μc‖ > τk ] ∧ [ verified ] (8)

In words: Ft is the batch of engineer decisions; Ztnormal are patch features from regions the engineers called normal, and Ztdefect features from confirmed, labelled defects. A candidate normal patch z enters the memory only if it is genuinely new (farther than δt, the median nearest-neighbour distance among current normal patches), is not similar to a known defect, and has been verified. Defect features update the class prototypes (⊕ = add the example and recompute the class mean). Mt+1 is kept only if the held-out regression check passes; otherwise Mt+1 = Mt.

19.8 Worked example of feature-based anomaly scoring

Use tiny 2-number features to keep the arithmetic visible. Suppose K = 2 references give four normal patch features at one aligned position window:

MN(p) = { (1.0, 2.0), (1.2, 1.9), (0.9, 2.1), (1.1, 2.2) }

Normal target patch fp(x) = (1.05, 2.05). Distances: to (1.0, 2.0) = √(0.05² + 0.05²) = 0.071; to (1.2, 1.9) = 0.212; to (0.9, 2.1) = 0.158; to (1.1, 2.2) = 0.158. Minimum: s(p) = 0.071.

Defective target patch (a bright particle raises both feature values) fp(x) = (2.0, 3.0). Distances: 1.414, 1.360, 1.421, 1.204. Minimum: s(p) = 1.204.

Threshold. Scoring held-out normal patches gives values between 0.03 and 0.25; with α = 1% suppose τpix = 0.30. The first patch (0.071) is normal; the second (1.204) is anomalous, and it is about 4× above the threshold, which is a confident decision.

Triage. Known prototypes: μparticle = (2.1, 3.1) with τk = 0.4; μscratch = (0.2, 0.5) with τk = 0.4. Distance of the region (2.0, 3.0) to μparticle = 0.141 < 0.4 → known: particle. A region at (3.5, 0.8) would be 2.69 from the particle prototype and 3.31 from the scratch prototype, beyond both τk → unknown anomaly, even though it is clearly anomalous (its distance to normal memory is large).
