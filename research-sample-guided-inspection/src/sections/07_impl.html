23.4 Pseudocode: reference enrolment

def enrol(reference_images, encoder, cfg):
    template = choose_template(reference_images)          # e.g. the most "central" reference
    items = []
    for r in reference_images:
        q = quality_check(r)
        if not q.ok: log.warn("reference rejected", q); continue
        r = normalize(r)                                  # global contrast only, no smoothing
        T = register(template, r)                         # canonical pose of this reference
        r_c, valid = warp(r, T)                           # references may be warped: they are clean
        for scale, fmap in encoder.extract(r_c).items():
            items += patches(fmap, valid, meta={ref_id, scale, position})
    items = memory_qc(items)       # leave-one-out outlier check, de-duplication, optional coreset
    M = Memory(items, version=0, provenance="enrolment", cfg_hash=hash(cfg))
    M.prototypes = build_prototypes(cfg.known_defects, encoder)   # optional, kept separate
    tau = calibrate_threshold(M, cfg.calibration_normals, alpha=cfg.alpha)
    return M, tau

23.5 Pseudocode: inference on a new die

def inspect(x, M, tau, encoder, cfg):
    q = quality_check(x)
    if not q.ok: return Result(status="REVIEW: image quality", quality=q)
    x = normalize(x)                                      # same operation as for references
    T, align_score = register(M.template, x)              # coarse 90° + Fourier–Mellin + ECC
    refs_in_x_frame, valid = warp_references(M.reference_images, T)   # target untouched
    feats = encoder.extract(x)                            # multi-scale feature maps of the target
    s_win = M.query(feats, window=cfg.window, aligned_to=T)           # Eq. (2), aligned search
    s_glob = M.query(feats, window=None)                  # global search, misalignment check
    S = smooth(upsample(combine_scales(s_win)), cfg.sigma) * valid    # Eq. (3)
    A = top_q_mean(S, cfg.q)
    regions = connected_regions(S > tau.pixel, min_area=cfg.min_area)
    for r in regions:
        r.label, r.distances = triage(region_feature(feats, r), M.prototypes)   # Eq. (5)
    status = ("NORMAL" if A <= tau.image else
              "UNKNOWN" if any(r.label == "unknown" for r in regions) else "SUSPICIOUS")
    conf = confidence(A, tau, agreement(s_win, s_glob), align_score)
    return Result(status, A, S, regions, conf, T, memory_version=M.version)

23.6 Pseudocode: feedback update

def feedback_round(M, batch, heldout, canary, cfg):
    cand_normal, cand_defect = [], []
    for fb in batch:                                    # fb: action, die, region, label, reviewer
        log.record(fb, memory_version=M.version)
        if fb.action == "reject":                         # false alarm: region is normal
            quarantine.add(features_in(fb.region), fb)
        elif fb.action in ("confirm", "label", "correct"):
            cand_defect += [(features_in(fb.corrected_region), fb.label)]
        elif fb.action == "unknown":
            investigation_set.add(fb)                     # never enters normal memory
    released = quarantine.release(min_votes=cfg.min_votes, second_review=cfg.second_review)
    delta = median_nn_distance(M.normal)                  # self-calibrating novelty gate
    for z in released:
        if nn_distance(z, M.normal) > delta and min_proto_distance(z, M.prototypes) > cfg.tau_k:
            cand_normal.append(z)                         # Eq. (8)
    M_new = M.snapshot().add_normal(cand_normal).update_prototypes(cand_defect)   # Eq. (7)
    before, after = evaluate(M, heldout), evaluate(M_new, heldout)
    drift_ok = evaluate(M_new, canary).recall >= evaluate(M, canary).recall - cfg.tol
    if after.recall_at_tau >= before.recall_at_tau and after.auroc >= before.auroc - cfg.tol and drift_ok:
        return M_new                                      # accepted: version t+1
    log.warn("update rejected, rolling back"); return M

23.8 Logging and evaluation strategy

  • Every run writes results/<experiment>/<timestamp>_<hash>/ containing the resolved config, the git commit, environment versions, split manifest hashes, metrics.json, per-image predictions (CSV) and a sample of anomaly maps.
  • Features are cached by image hash and encoder name, so experiments that only change scoring do not recompute features.
  • Reported tables are generated by a script from metrics.json files, never typed by hand.
  • Unit tests: AUPRO and DPR on hand-made cases; alignment recovers known synthetic transforms within a tolerance; the leakage checker fails on a deliberately leaked manifest.
  • Compute budget: on one consumer GPU (8–12 GB), WRN-50 features for a 448 × 448 tile take on the order of tens of milliseconds and K ≤ 10 memories fit easily in memory; everything also runs (slowly) on CPU. This is an estimate to be confirmed in milestone 3, not a measurement.

26.2 Critical feasibility assessment

Is a small reference collection sufficient? For same-wafer inspection of a stable process, probably yes for clear defects: published few-shot results on natural-object benchmarks are strong at K = 1–4 [[anomalydino,graphcore]]. For subtle defects close to the natural variation, no: K = 1 sees one sample of "normal", so false alarms and thresholds will be poorly controlled. Experiment A measures where the curve flattens; the honest expectation is that K = 5–10 is needed for stable thresholds.

Can normal-only references identify all defect types? No. They cannot identify (i) defects that look normal at the encoder's resolution; (ii) systematic defects present in every reference; (iii) defects whose appearance falls within natural variation (low-contrast stains under strong illumination change); (iv) "logical" defects in which every part looks normal but something is in the wrong place, unless matching is position-aware. The windowed (aligned) search partly addresses (iv); (ii) needs design data or golden references [[cantu2025]].

Are different wafer types different enough to break transfer? Different designs, yes: a memory of design X contains no normal example of design Y (Scenario 2b), so it must be re-enrolled. Different wafers of the same design differ by process drift and imaging conditions; the size of the effect is an empirical question (Experiment D), and domain-shift studies on SEM classification suggest it is not negligible [[poniatowski]].

Can rotation normalisation remove meaningful defect information? Yes. Warping the target resamples it, which blurs 1–2 px defects and can cut defects near borders; rotation-invariant features cannot distinguish a correctly shaped but wrongly oriented structure. The design (warp references, mask borders) and the DPR metric exist to measure and limit this; it is not assumed to be solved.

Do public datasets support cross-wafer evaluation? No (Section 17.7). Cross-wafer claims rest on synthetic wafers unless partner data is obtained. This is the most important limitation of the study, and it is stated in every result table.

Are pixel-level masks available? Yes for SEM (Carinthia-S) and for natural-object sets; no for the die-level optical set (boxes only). Pixel-level claims on patterned dies come from synthetic data only.

Does feedback improve detection or merely memorise samples? That is exactly what Experiment G tests: improvement is measured only on dies that never generated feedback, with a "random extra normals" control. Abbas et al. showed that naive evaluation inflates gains through memorisation [[abbas]]. If held-out gains vanish, the conclusion is that feedback only memorises, which is still a useful negative result.

Can the system run with limited GPU resources? Yes for the core: frozen encoders, cached features and K ≤ 10 memories fit a consumer GPU, and the toy pipeline runs on a laptop CPU. Large foundation-model baselines (UniVAD, CLIP-based) may be too heavy; they are optional. Self-supervised SEM pre-training is the only component that needs substantial compute, and it is an extension.

26.3 Smallest scientifically meaningful prototype

Minimum viable study (about 16–20 weeks)
  1. PatchCore-style memory with WRN-50 and DINOv2 encoders, reproduced on MVTec AD (sanity gate).
  2. Few-shot curves K = 1, 2, 5, 10 on Carinthia-S and Wafer Surface Defect (Experiment A).
  3. Rotation sweep with four pipelines and DPR on injected defects, on Carinthia-S and a small synthetic die set (Experiment B, Contribution C2).
  4. Leave-one-class-out unknown triage on Carinthia-S (Experiment E, Contribution C3).

This already answers RQ1, RQ2 and RQ4 with public data and is publishable as a workshop or conference paper if executed carefully. Everything else builds on it.

27Expected Contributions

If the plan is carried out, the expected outputs are listed below. These are outputs of the work, not predicted outcomes; each hypothesis may be confirmed or rejected.

  1. An evaluated, open reference-memory inspector for die images covering K-shot enrolment, alignment, localisation, triage and gated updates, with reproducible configurations.
  2. Evidence on defect-preserving alignment (C2): a comparison of no alignment, target warping, reference warping, rotation-augmented memories and invariant features under a full rotation sweep, with the defect preservation ratio as a reusable evaluation tool.
  3. Evidence on unknown-defect triage (C3): leave-one-class-out results on public SEM masks showing how often unfamiliar defects are flagged as unknown versus forced into known classes.
  4. Evidence on safe feedback (C5): held-out measurements of whether verified memory edits help, and how gating and rollback behave under realistic error rates.
  5. A transfer protocol (C1): explicit same-wafer / cross-wafer / cross-type splits and a synthetic patterned-wafer benchmark with exact ground truth, released for others to use.
  6. Negative results where they occur, for example if reference-free intrinsic normality [[zhao2025seg]] beats reference memories on unpatterned SEM, or if feedback gains vanish on held-out data.

28Conclusion

The research idea, "give the AI a few sample dies, let it learn their patterns, inspect new dies, show where the defects are, and improve from verified feedback", is technically feasible with existing building blocks. Frozen pretrained encoders and a reference memory provide few-shot learning without retraining; classical registration applied to the references keeps targets untouched; nearest-neighbour distances give interpretable anomaly maps; distance-based open-set triage keeps unknown defects visible; and memory edits make feedback auditable and reversible.

The literature shows that each block exists, so novelty must come from the combination, the semiconductor setting and the evaluation: whether alignment preserves defects, whether unknown defects are localised and kept apart from known ones, whether feedback survives realistic mistakes, and how transfer differs between same-wafer, cross-wafer and cross-type inspection. The main limitation is data: no public patterned-die dataset with masks and wafer coordinates exists, so cross-wafer conclusions will rest on synthetic data unless partner data becomes available.

What to do first: reproduce PatchCore on MVTec AD; run few-shot curves on Carinthia-S; build the rotation sweep with "warp the reference" and the DPR metric; then add unknown triage. That sequence produces a meaningful result within about four months and lays the foundation for the feedback study.
